# lm_corpus — 語言模型文字語料（純文字，不需音檔）

用途：擴充 char n-gram 語言模型（`experiments/ngram_lm/char_4gram.pkl`），
改善即時辨識的**選字**（同音/近音挑錯字），並切出 held-out 量**誤改率**。
背景見 `_decisions/2026-06-22 選字問題策略 — 辭典 vs 語言模型`（Obsidian）。

> ⚠️ 這裡只放**文字**。語言模型不需要對應的語音檔案。

## 放哪
- `meeting_records/` — 會議記錄（捷運營運相關）。詞彙來源佳；語體偏書面。
- `seat_transcripts/` — 席位間對話逐字稿。**口語語體最匹配，是最佳語料**。

兩類都丟 `.txt` 進對應子資料夾即可，檔名隨意（建議帶日期/主題）。

## 格式（與 GT 標準一致）
- 純文字 `.txt`、**UTF-8**、**正體中文**。
- **一句一行**（依句號/語氣斷句換行）—— n-gram 以行為句界算 BOS/EOS，分行越乾淨越準。
- **不分講者**（不要寫「站長：」「OCC：」之類前綴；同 [[2026-06-05 GT 產製標準 — 不分講者]]）。
- **忠實逐字**：席位逐字稿請逐字聽打（含口語贅詞），不要摘要；會議記錄照原文即可。
- 數字/英文/代碼照原樣（清理交給程式，不必手動正規化）。

## 範例（seat_transcripts/某檔.txt）
```
等一下那個一號月台的列車先停一下。
收到，先停一號月台。
電力那邊確認一下狀況再回報。
```

## 之後流程（你存好、跟我說，我來做）
1. 把這裡的文字併入 `build_ngram_lm.py` 語料 → 重建 `char_4gram.pkl`。
2. 切 held-out → 量**誤改率**（拿正確句餵 `HomophoneCorrector`，數它有沒有亂改）。
3. 誤改率達標 → 才把 `enable_homophone_lm=True` 接進 `app_api` 即時路徑。
