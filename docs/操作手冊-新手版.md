# 🎙️ aiSpeechMulti 新手操作手冊

> **目的**：讓新手在 30 分鐘內把全部介面點過一輪，建立對系統的整體感受，並從體驗中針對版面配置提出改善建議。
> **適用對象**：第一次使用 aiSpeechMulti 的同事。
> **不需要**：寫程式、改設定檔。
> **需要**：一台已 setup 好的 Mac、瀏覽器、麥克風（試即時辨識時用）。

---

## 🚦 0 · 在你開始之前

### 三個主入口（先記在心裡）

| 入口 | 網址 | 用途 | 第一感受 |
|---|---|---|---|
| 即時操作 | http://localhost:8000 | OCC 現場、操作員、控制室 | 暗色、即時字幕 |
| 研究操作台 (Lab) | http://localhost:8501 | 跑檔案、查資料、改詞彙 | 9 個分頁 |
| 維運監控 (Grafana) | http://localhost:3000 | 看趨勢、看統計 | 暗色 dashboard |

### 推薦動線（30 分鐘走完）

```
1. 啟動服務 (5 min)
   ↓
2. :8000 看 landing → capture / monitor / display 各 1 分鐘 (5 min)
   ↓
3. :8501 Lab → 9 個分頁各看 30 秒 (10 min)
   ↓
4. :3000 Grafana → 滑過 7 大區塊 (5 min)
   ↓
5. 完整跑一輪：上傳音檔 → 查歷史 → 加一個關鍵字 (5 min)
```

## 🟢 1 · 啟動服務（每次開始都要做）

### 1.1 啟用 Python 環境

打開 Terminal，cd 到專案目錄：

```bash
cd ~/Projects/projectArea/aiSpeechMulti
source ./activate.sh
```

> ✅ 看到 `Python 3.x.x` 字樣就成功。

### 1.2 一鍵啟動 FastAPI + Streamlit Lab

```bash
python -m aispeech serve all
```

> ✅ 終端機會出現兩段訊息：
> - `Uvicorn running on http://0.0.0.0:8000`
> - `You can now view your Streamlit app in your browser. Local URL: http://localhost:8501`
>
> **不要關掉這個 terminal**——關掉服務就停了。要停服務按 `Ctrl+C`。

### 1.3 啟動 Grafana（選用，看 dashboard 才需要）

開**另一個** Terminal：

```bash
docker compose -f ~/Projects/projectArea/aiSpeechMulti/grafana/docker-compose.yml up -d
```

> ✅ 跑完不會印很多訊息，安靜就是成功。
> 登入：帳號 `admin` / 密碼 `aiSpeech2026`（首次登入會要你改密碼）。

## 🎤 2 · 即時語音辨識（場景：現場開麥克風）

### 2.1 開 capture 頁面（錄音端）

瀏覽器 → http://localhost:8000/capture

版面結構：

```
┌────────────────────────────────────┐
│ 🔗 連線設定                        │
│   席位代號:  [ch1 控制長 ▼]       │
│   串流模式:  [dual ▼]             │
│   引擎:      [google ▼]           │
│   伺服器:    [ws://localhost:8000]│
│              [ 開始監聽 ]          │
├────────────────────────────────────┤
│ 🎙️ 音訊輸入裝置                   │
│   裝置:      [預設麥克風 ▼]       │
│              [ 掃描裝置 ]          │
├────────────────────────────────────┤
│ ⚙️ 音訊前處理                      │
│   ☐ VAD 靜音過濾 (threshold 0.5)  │
│   ☐ DeepFilterNet 降噪            │
└────────────────────────────────────┘
```

### 2.2 怎麼點選（從上到下）

| 你要做的 | 對應動作 |
|---|---|
| 選你坐的位置 | **席位代號** dropdown → ch1~ch6（ch1=控制長 / ch2=MTC / ch3=DTC / ch4=PC / ch5=EC / ch6=IA） |
| 選辨識方式 | **串流模式** dropdown → 預設 `dual`（推薦） |
| 選辨識引擎 | **引擎** dropdown → 預設 `google`（chirp_3） |
| 選麥克風 | 先按 **掃描裝置**，再從 dropdown 挑你要用的 |
| 開始辨識 | 按 **開始監聽**（變紅表示正在錄，再按一次停止） |

### 2.3 五種「串流模式」差異速查

| 模式 | 延遲 | 來源 | 何時用 |
|---|---|---|---|
| **`dual`** ⭐ | ~150ms | Scribe 即時 + Google 批次確認 | **預設、最穩** |
| `scribe_rt` | ~150ms | 純 ElevenLabs Scribe | 想最快 |
| `google_stream` | ~500ms | Google streaming | 對照組 |
| `sensevoice_local` | ~1s | 本機離線 | 機密、無網路 |
| `batch` | ~15s | Google 批次（15 秒一段）| 不在意即時 |

### 2.4 同時開另一個分頁看 monitor

瀏覽器**新分頁** → http://localhost:8000/monitor

你會看到：
- **頂部 💰 status bar**：「今日 NT$ X · session NT$ Y · N/6 席位活動中」
- **6 路席位欄**：每欄三區（左：席位名稱 / 中：即時字幕滾動 / 右：每席統計）
- **點 ▼ 展開**：按引擎細分的成本拆解

> ✅ 對著麥克風講話，字幕應從 capture 流進 monitor 對應席位欄。

### 2.5 給控制室大螢幕看的 display

瀏覽器**新分頁** → http://localhost:8000/display

特色：
- **超大字**（5 公尺外可讀）
- **關鍵字依 alert_level 放大 + 變色**
- 緊急事件出現 **頂部閃爍橫幅**
- 工具列可隱藏（右上 hide 鍵）

> - monitor 6 路席位欄寬度合理嗎？
> - display 在你的螢幕上字夠大嗎？

## 📁 3 · 語音檔案辨識（場景：拿一段錄音想看辨識結果）

### 3.1 開 Lab 的 speech 分頁

瀏覽器 → http://localhost:8501

左 sidebar 預設停在 **🎙️ 批次辨識**（如果不在這頁，從 sidebar 點它）。

### 3.2 五個步驟（從上往下做）

```
Step 1 · 選模型類別
  ◯ google_stt   ◯ sensevoice   ◉ sensevoice_ft   ◯ gemini   ◯ hybrid

Step 2 · 選子模型
  Google → ◉ chirp_3  ◯ chirp_3_hans
  Gemini → ◉ gemini-2.5-pro  ◯ gemini-2.5-flash  ◯ gemini-3.1-pro

Step 3 · 上傳音檔
  [ 📁 上傳本機檔案 ] [ 🔍 瀏覽伺服器音檔 ]
  ↑ 拖拉 wav/mp3/m4a/flac/ogg/aac 上來

Step 4 · 詞彙表設定
  ☑ 啟用詞彙加權
     三層架構：PhraseSet（引擎內）/ term_filter（後處理）/ correction_dict（修正）

Step 5 · 音訊前處理
  ☐ VAD     ☐ DeepFilterNet 降噪

  [ 🚀 開始辨識 ]
```

### 3.3 看結果

按 **🚀 開始辨識** → 切到 running 頁面 → 跑完顯示：

- **raw**：原始辨識
- **4 階段後處理**：car_norm → dict → contextual → LLM
- **信心度色塊**：低信心字會黃底
- **✏️ 修正**按鈕：人工修錯（會進飛輪）

> - 「詞彙加權」的說明看得懂嗎？

## 📚 4 · 建立關鍵字庫（詞彙表）

> 場景：你發現「OCC 收到」常被辨識成「OCC 受到」，想加進詞彙表。

### 4.1 開 Lab vocabulary 分頁

Lab sidebar → 點 **📚 詞彙表**

版面：

```
[篩選列]
  搜尋: [_____]   類別: [全部 ▼]   告警等級: [全部 ▼]

[編輯表格 — 像 Excel]
  term         category   boost  alert  pinyin    common_error    description
  ─────────────────────────────────────────────────────────────────────────
  OCC收到      OCC術語     15     0      ...       OCC受到         控制中心回應...
  月台門故障   設備故障    20     3      ...       月台門姑章      ...
  ...

  [ 💾 儲存變更 ]

[➕ 新增詞條]    (展開式表單)

[🗑️ 刪除詞條]   [⬇️ 下載詞彙表 CSV]
```

### 4.2 新增詞條（最常用）

1. 捲到頁面下方 **➕ 新增詞條**（點展開）
2. 填欄位（**術語** 必填）：

   | 欄位 | 範例 | 說明 |
   |---|---|---|
   | 術語 | `OCC收到` | 想加進的詞 |
   | 類別 | `OCC術語` | 分類，方便後續篩選 |
   | 加權值 | `15` | 給 Google PhraseSet 用 |
   | 告警等級 | `0` | 0~5（0=普通 / 5=最高） |
   | 拼音 | `OCC shōudào` | 選填 |
   | 常見錯誤 | `OCC受到, OCC收道` | 會被替換成正確版 |
   | 說明 | `控制中心回應確認用語` | 給人看 |

3. 按 **✅ 新增**

### 4.3 修改現有詞條

中間表格直接點該列要改的儲存格 → 改完按上方 **💾 儲存變更**。

### 4.4 詞彙表的三層架構（先了解概念）

```
基底：    vocabulary/term_filter.json          ← 所有引擎共用
覆寫：    vocabulary/engines/{engine}.json     ← 特定引擎的額外規則
動態：    vocabulary/contextual_corrections.json ← 前後文修正
```

新手先動「基底」就好，引擎覆寫等熟了再玩。

## 📊 5 · 計算 CER（字錯誤率）

CER = Character Error Rate，越低越準（0% 完美，100% 全錯）。

### 5.1 在 Lab 跑一次評測

Lab sidebar → 點 **📊 準確率評測**

操作（4 步）：

1. **選案例**：頂部 dropdown 挑 `experiments/` 下的子目錄（或點 **➕ 新建案例**）
2. **上傳音檔**：拖到「source_audio」上傳區
3. **上傳 ground truth**：拖 `.txt` / `.csv` 到「ground_truth」上傳區
4. **上傳 ASR output**：拖辨識結果到「asr_output」上傳區 → 按 **開始評測**

結果顯示：
- **CER %**（最重要）
- **字元對照 diff**（紅色刪 / 綠色加）

### 5.2 用 CLI 跑 6 引擎全批次

回 Terminal：

```bash
python -m aispeech eval-batch
```

> ✅ 結果存到 `experiments/llm_correction_poc/cer_history.csv`
> 想看趨勢 → `python -m aispeech data sync-cer` → 開 Grafana 看 CER 趨勢

---

> ✏️ **請新手回饋**
> - 「評測」這個詞新人聽得懂嗎？或應叫「準確率測試」？
> - 結果頁的 CER 數字位置夠醒目嗎？

## 🔍 6 · 查詢歷史辨識結果

### 6.1 全文搜尋（Lab）

Lab sidebar → 點 **🔍 全文搜尋**

操作：
1. **搜尋關鍵字** 輸入框 → 例：`疏散` / `月台門故障` / `OCC 收到`
2. 右邊選 **最多顯示筆數**：20 / 50 / 100 / 200
3. 按 Enter 或點搜尋按鈕

結果格式：

```
📁 {事件名} ｜ {檔名} ｜ {時間}
   ...內文，命中字用橘色高亮...
```

> 💡 ≥3 字會走 FTS5 全文索引（快），<3 字會走 LIKE（慢）。

### 6.2 看單一事件 + 修正辨識（Lab 事件管理）

Lab sidebar → 點 **🗂️ 事件管理**

操作：
1. 頂部 dropdown 選事件，格式：`[L{hazard}] 日期 事件名 (model/sub)`
2. **⚠️ 危害等級** dropdown → 選 L0~L5 → **💾 更新**
3. **📝 備注** text area → 寫筆記 → **💾 儲存備注**
4. 下方 **📄 辨識結果** 逐筆展開，每筆有：
   - raw 文字
   - **可編輯的「修正後文字」框** + 儲存按鈕
5. 修正會自動進入飛輪 → overlay → 下次更準

### 6.3 看趨勢（Grafana）

http://localhost:3000 → 找 dashboard 「**aiSpeechMulti 語音辨識監控**」

7 大區塊：

| # | 區塊 | 內容 |
|---|---|---|
| 1 | 📊 整體統計 | 總筆數、引擎分布、危害分布 |
| 2 | 📈 辨識量趨勢 | 每小時 / 每日 |
| 3 | 🔍 引擎與管道分析 | 各引擎成功率 |
| 4 | ⚠️ 關鍵字危害分析 | 危害分布 + Top 關鍵字 |
| 5 | 🎙️ 最近辨識記錄 | 近 50 筆 transcripts |
| 6 | 📁 檔案辨識評測記錄 | batch_eval 結果 |
| 7 | 📈 CER 趨勢 | 各引擎 CER 隨時間變化 |

### 6.4 用 API 撈（給開發人員）

```bash
curl http://localhost:8000/api/transcripts?event_name=20260321_車站演練&limit=20
curl http://localhost:8000/api/usage/today
curl http://localhost:8000/api/channels
```

## ⚠️ 7 · 關鍵字告警介面

> 目前 aiSpeechMulti **沒有單獨的「告警頁」**，告警散在三個介面：

### 7.1 即時告警 — display.html（控制室大螢幕）

辨識文字命中 alert_level≥3 的詞時：

| 等級 | display 視覺 |
|---|---|
| L1-L2 | 變色文字（正常大小） |
| L3-L4 | **放大 1.5×** + 變色 |
| L5 | 放大 + **發光描邊** + **頂部閃爍橫幅** |

打開：http://localhost:8000/display

### 7.2 即時告警 — monitor.html（操作員監看）

命中危害詞的整列字幕背景變色（`.transcript--hazard` 樣式）。

打開：http://localhost:8000/monitor

### 7.3 事後告警分析 — Grafana

dashboard 第 4 區塊「**⚠️ 關鍵字危害分析**」：
- 危害等級分布長條圖
- 高頻關鍵字 Top N
- 各席位危害次數比較

### 7.4 怎麼新增 / 修改告警關鍵字

回到 **第 4 節 Lab 詞彙表** → 設該詞的 **告警等級**：

| 等級 | display 視覺 | monitor 視覺 |
|---|---|---|
| 0 | 普通 | 普通 |
| 1-2 | 變色文字 | 變色 |
| 3-4 | 放大 1.5× + 變色 | 背景變色 |
| 5 | 放大 + 描邊 + 閃爍 banner | 背景變紅 |

## 🆘 9 · 常見問題

| 狀況 | 怎麼處理 |
|---|---|
| 開 http://localhost:8000 顯示「無法連線」 | 回 Terminal 看 `python -m aispeech serve all` 還在不在跑 |
| capture 按 **開始監聽** 沒反應 | macOS 系統設定 → 安全性 → 麥克風權限 |
| 上傳音檔顯示「Unsupported format」 | 只接受 wav / mp3 / m4a / flac / ogg / aac |
| Grafana 進不去 | Docker Desktop 沒開，或 `docker compose` 沒跑 |
| 字幕跑出來是亂碼 | 引擎選錯（中文要選 chirp_3 / chirp_3_hans / SenseVoice） |
| Lab 開啟很慢 | 第一次載入要編譯 Streamlit，等 30 秒即可 |
