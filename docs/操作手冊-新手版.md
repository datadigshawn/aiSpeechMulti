# 🎙️ aiSpeechMulti 新手操作手冊

> **目的**：讓新手快速理解系統架構、啟動服務，並走完完整操作流程。
> **適用對象**：第一次使用 aiSpeechMulti 的同事。
> **不需要**：寫程式、改設定檔。
> **需要**：一台已 setup 好的 Mac（含 conda 環境）、瀏覽器、麥克風（試即時辨識時用）。

## 🗺️ 0 · 系統架構一覽

### 三層介面架構

```
┌─────────────────────────────────────────────────────────┐
│                   aiSpeechMulti                         │
│            六路無線電語音即時辨識平台                    │
├──────────────┬────────────────┬────────────────────────┤
│ 即時層       │ 研究層         │ 運維層                  │
│ :8000        │ :8501          │ :3000                   │
│              │                │                         │
│ landing      │ Streamlit Lab  │ Grafana Dashboard       │
│ capture      │ 9 個分頁       │ 7 個 row / 25 panels    │
│ monitor      │                │                         │
│ display      │                │                         │
│              │                │                         │
│ 場域/操作員  │ 開發/評測者    │ SRE/開發                │
│ 毫秒級 WS    │ 互動觸發       │ 分鐘級輪詢              │
└──────────────┴────────────────┴────────────────────────┘
                        ↑ 共用 ↑
               SQLite + FTS5 (data/aiSpeechMulti.db)
               python -m aispeech（統一 CLI）
```

### 六個 STT 引擎（按當前 CER 排序）

| 引擎 | 類型 | CER（159段GT） | 說明 |
|---|---|---|---|
| **SenseVoice FT v2** ⭐ | 離線/本機 | **25.42%** | LoRA fine-tune，捷運通訊專用，零成本 |
| Gemini 2.5 Pro | 雲端 | ~28% | 語意理解最強，有成本 |
| Google chirp_3 | 雲端 | ~40% | 適合即時串流，穩定 |
| ElevenLabs Scribe | 雲端/RT | ~50% | 即時感最好（~150ms） |
| SenseVoice (base) | 離線/本機 | ~65% | 無 fine-tune 的基底 |
| Whisper | 離線/本機 | ~70% | 通用模型 |

> **當前主力策略**：`dual` 即時模式（Scribe RT + Google batch），批次評測選 SenseVoice FT v2。

### 資料流（dual 即時模式）

```
Browser ×6 (PCM 16kHz)
    │ WebSocket /ws/stream/{ch1-ch6}?mode=dual
    ▼
FastAPI asyncio
    ├─→ Scribe v2 RT  ──→ partial → 前端  (~150ms TTFT)
    └─→ AudioBuffer (15s) → Google STT chirp_3 → confirmed
                                    │
                                    ▼
                            post_process 4 階段
                            ├─ car_norm (regex 數字)
                            ├─ dict (term_filter + engine overlay)
                            ├─ contextual (prefix/suffix 規則)
                            └─ LLM correction (Gemini, 可關)
                                    │
                                    ▼
                            SQLite + FTS5 → Grafana
```

### 後處理飛輪（CER 持續改善的核心機制）

```
✏️ 控制室人工修正
    ↓ Lab「修正歷程」頁存進 DB
    ↓ python -m aispeech data export-feedback
🌱 vocabulary/engines/{engine}.feedback-draft.json
    ↓ review 改名為 .json，重啟服務套用
🔄 下次辨識 CER ↓
```

## 🟢 2 · 啟動服務（每次開始都要做）

### 2.1 啟用 conda 環境

打開 Terminal，cd 到專案目錄：

```bash
cd ~/Projects/projectArea/aiSpeechMulti
source ./activate.sh
```

> ✅ 看到 `已啟動 conda 環境：aiSpeech_project_nightly` 就成功。
>
> 如需切回穩定版：`source ./activate.sh stable`

### 2.2 確認 API Keys 設定（第一次才需要）

系統需要以下環境變數或 `utils/api_keys.json`（推薦，優先於 .env）：

```json
// utils/api_keys.json（已加入 .gitignore，不入 git）
{
  "GEMINI_API_KEY": "your-gemini-key",
  "GOOGLE_CLOUD_PROJECT": "your-gcp-project-id"
}
```

或用 `.env`（從 `.env.example` 複製）：

```
GOOGLE_APPLICATION_CREDENTIALS=./utils/google-speech-key.json
ELEVENLABS_API_KEY=sk_...
```

> ⚠️ 安全注意：`.env`、`utils/api_keys.json`、`utils/*-key.json` 全部在 `.gitignore`。
> **永遠不要**把 API key 提交進 git。

### 2.3 一鍵啟動 FastAPI + Streamlit Lab

```bash
python -m aispeech serve all
```

> ✅ 終端機會出現兩段訊息：
> - `Uvicorn running on http://0.0.0.0:8000`
> - `You can now view your Streamlit app in your browser. Local URL: http://localhost:8501`
>
> **不要關掉這個 terminal**——關掉服務就停了。要停服務按 `Ctrl+C`。

也可以分開啟動：

```bash
# 只起 API（即時辨識）
python -m aispeech serve api

# 只起 Lab（研究工作台）
python -m aispeech serve lab
```

### 2.4 啟動 Grafana（選用，看 dashboard 才需要）

開**另一個** Terminal：

```bash
docker compose -f ~/Projects/projectArea/aiSpeechMulti/grafana/docker-compose.yml up -d
```

> ✅ 跑完不會印很多訊息，安靜就是成功。
> 登入：帳號 `admin` / 密碼 `aiSpeech2026`（首次登入會要你改密碼）。

## 🎤 3 · 即時語音辨識（場景：現場開麥克風）

### 3.1 開 capture 頁面（錄音端）

瀏覽器 → http://localhost:8000/capture

版面結構：

```
┌────────────────────────────────────┐
│ 🔗 連線設定                        │
│   席位代號:  [ch1 控制長 ▼]       │
│   串流模式:  [dual ▼]             │
│   引擎:      [google ▼]           │
│   伺服器:    [ws://localhost:8000]│
│              [ 開始監聽 ]          │
├────────────────────────────────────┤
│ 🎙️ 音訊輸入裝置                   │
│   裝置:      [預設麥克風 ▼]       │
│              [ 掃描裝置 ]          │
├────────────────────────────────────┤
│ ⚙️ 音訊前處理                      │
│   ☐ VAD 靜音過濾 (threshold 0.5)  │
│   ☐ DeepFilterNet 降噪            │
└────────────────────────────────────┘
```

### 3.2 怎麼點選（從上到下）

| 你要做的 | 對應動作 |
|---|---|
| 選你坐的位置 | **席位代號** dropdown → ch1~ch6（ch1=控制長 / ch2=MTC / ch3=DTC / ch4=PC / ch5=EC / ch6=IA） |
| 選辨識方式 | **串流模式** dropdown → 預設 `dual`（推薦） |
| 選辨識引擎 | **引擎** dropdown → 預設 `google`（chirp_3） |
| 選麥克風 | 先按 **掃描裝置**，再從 dropdown 挑你要用的 |
| 開始辨識 | 按 **開始監聽**（變紅表示正在錄，再按一次停止） |

### 3.3 五種「串流模式」差異速查

| 模式 | 延遲 | 來源 | 何時用 |
|---|---|---|---|
| **`dual`** ⭐ | ~150ms | Scribe 即時 + Google 批次確認 | **預設、最穩** |
| `scribe_rt` | ~150ms | 純 ElevenLabs Scribe | 想最快 |
| `google_stream` | ~500ms | Google streaming | 對照組 |
| `sensevoice_local` | ~1s | 本機離線 | 機密、無網路 |
| `batch` | ~15s | Google 批次（15 秒一段）| 不在意即時 |

### 3.4 同時開另一個分頁看 monitor

瀏覽器**新分頁** → http://localhost:8000/monitor

你會看到：
- **頂部 💰 status bar**：「今日 NT$ X · session NT$ Y · N/6 席位活動中」
- **6 路席位欄**：每欄三區（左：席位名稱 / 中：即時字幕滾動 / 右：每席統計）
- **點 ▼ 展開**：按引擎細分的成本拆解

> ✅ 對著麥克風講話，字幕應從 capture 流進 monitor 對應席位欄。

### 3.5 給控制室大螢幕看的 display

瀏覽器**新分頁** → http://localhost:8000/display

特色：
- **超大字**（5 公尺外可讀）
- **關鍵字依 alert_level 放大 + 變色**
- 緊急事件出現 **頂部閃爍橫幅**
- 工具列可隱藏（右上 hide 鍵）

## 📁 4 · 語音檔案辨識（場景：拿一段錄音想看辨識結果）

### 4.1 開 Lab 的 speech 分頁

瀏覽器 → http://localhost:8501

左 sidebar 預設停在 **🎙️ 批次辨識**（如果不在這頁，從 sidebar 點它）。

### 4.2 五個步驟（從上往下做）

```
Step 1 · 選模型類別
  ◯ google_stt   ◯ sensevoice   ⭐ sensevoice_ft（推薦）   ◯ gemini   ◯ hybrid

Step 2 · 選子模型（sensevoice_ft 時）
  ◉ SenseVoice + LoRA r32 e60 v2 (113段) — 捷運通訊專用（CER 25.42%）

Step 3 · 上傳音檔
  [ 📁 上傳本機檔案 ] [ 🔍 瀏覽伺服器音檔 ]
  ↑ 拖拉 wav/mp3/m4a/flac/ogg/aac 上來

Step 4 · 詞彙表設定
  ☑ 啟用詞彙加權
     三層架構：PhraseSet（引擎內）/ term_filter（後處理）/ correction_dict（修正）

Step 5 · 音訊前處理
  ☐ VAD     ☐ DeepFilterNet 降噪
  （注意：chirp_3/Scribe 有內建 AGC，外加降噪反而可能升 CER）

  [ 🚀 開始辨識 ]
```

### 4.3 引擎選擇建議

| 場景 | 推薦引擎 | 原因 |
|---|---|---|
| 捷運通訊錄音，離線或省錢 | **SenseVoice FT v2** ⭐ | CER 25.42%，零成本，快 |
| 要語意理解或 LLM 後修正 | gemini-2.5-pro | 語意最強，但有費用 |
| 即時串流（現場） | dual（Scribe + Google）| 延遲最低 |
| 敏感資料，絕對不上雲 | sensevoice_local | 純本機 |

### 4.4 看結果

按 **🚀 開始辨識** → 切到 running 頁面 → 跑完顯示：

- **raw**：原始辨識
- **4 階段後處理**：car_norm → dict → contextual → LLM
- **信心度色塊**：低信心字會黃底
- **✏️ 修正**按鈕：人工修錯（會進飛輪）

## 📚 5 · 建立關鍵字庫（詞彙表）

> 場景：你發現「OCC 收到」常被辨識成「OCC 受到」，想加進詞彙表。

### 5.1 開 Lab vocabulary 分頁

Lab sidebar → 點 **📚 詞彙表**

版面：

```
[篩選列]
  搜尋: [_____]   類別: [全部 ▼]   告警等級: [全部 ▼]

[編輯表格 — 像 Excel]
  term         category   boost  alert  pinyin    common_error    description
  ─────────────────────────────────────────────────────────────────────────
  OCC收到      OCC術語     15     0      ...       OCC受到         控制中心回應...
  月台門故障   設備故障    20     3      ...       月台門姑章      ...

  [ 💾 儲存變更 ]

[➕ 新增詞條]    (展開式表單)

[🗑️ 刪除詞條]   [⬇️ 下載詞彙表 CSV]
```

### 5.2 新增詞條（最常用）

1. 捲到頁面下方 **➕ 新增詞條**（點展開）
2. 填欄位（**術語** 必填）：

   | 欄位 | 範例 | 說明 |
   |---|---|---|
   | 術語 | `OCC收到` | 想加進的詞 |
   | 類別 | `OCC術語` | 分類，方便後續篩選 |
   | 加權值 | `15` | 給 Google PhraseSet 用 |
   | 告警等級 | `0` | 0~5（0=普通 / 5=最高） |
   | 拼音 | `OCC shōudào` | 選填 |
   | 常見錯誤 | `OCC受到, OCC收道` | 會被替換成正確版 |
   | 說明 | `控制中心回應確認用語` | 給人看 |

3. 按 **✅ 新增**

### 5.3 修改現有詞條

中間表格直接點該列要改的儲存格 → 改完按上方 **💾 儲存變更**。

### 5.4 詞彙表的三層架構（先了解概念）

```
基底：    vocabulary/term_filter.json            ← 所有引擎共用
覆寫：    vocabulary/engines/{engine}.json       ← 特定引擎的額外規則
         （gemini25pro / scribe / sensevoice / chirp3 / sensevoice_ft）
動態：    vocabulary/contextual_corrections.json ← 前後文修正
```

新手先動「基底」就好，引擎覆寫等熟了再玩。

## 📊 6 · 計算 CER（字錯誤率）

CER = Character Error Rate，越低越準（0% 完美，100% 全錯）。
目前黃金語料集：**159 段**（涵蓋 emergency / control / door / track 場景）。

### 6.1 在 Lab 跑一次評測

Lab sidebar → 點 **📊 準確率評測**

操作（4 步）：

1. **選案例**：頂部 dropdown 挑 `experiments/` 下的子目錄（或點 **➕ 新建案例**）
2. **上傳音檔**：拖到「source_audio」上傳區
3. **上傳 ground truth**：拖 `.txt` / `.csv` 到「ground_truth」上傳區
4. **上傳 ASR output**：拖辨識結果到「asr_output」上傳區 → 按 **開始評測**

結果顯示：
- **CER %**（最重要）
- **字元對照 diff**（紅色刪 / 綠色加）

### 6.2 用 CLI 批次跑全引擎評測

回 Terminal：

```bash
# 批次跑 6 引擎 × 159 段 golden dataset
python -m aispeech eval-batch

# CER CSV 同步進 SQLite（供 Grafana 看趨勢）
python -m aispeech data sync-cer
```

> ✅ 結果存到 `experiments/llm_correction_poc/cer_history.csv`
> 跑完後開 Grafana :3000 → CER 趨勢 row 看各引擎趨勢

### 6.3 當前最佳 CER 速查

| 引擎 | test CER | 說明 |
|---|---|---|
| SenseVoice FT v2 + LLM | **25.42%** | 59 段 test，+full pipeline |
| SenseVoice FT v2 raw | 26.20% | 無後處理 |
| Gemini 2.5 Pro | ~28% | 含 overlay + 預處理 |

## 🤖 9 · Fine-tune 工作流（M2 ↔ Windows 3090）

> 這段給需要跑或管理 SenseVoice Fine-tune 的人。一般使用者不需要動。

### 9.1 工作流架構

```
M2（開發/標注）                   Windows 3090（GPU 訓練）
      │                                    │
      │  ./scripts/sync_to_3090.sh up      │
      │  git push + rsync/scp audio ──────►│ git pull + 拿到音檔
      │                                    │
      │                                    │ python -m aispeech finetune
      │                                    │   --mode lora --lora-rank 32 --epochs 60
      │                                    │
      │  ./scripts/sync_to_3090.sh down    │
      │◄────────────── 拉 checkpoint ──────│ finetune_runs/sensevoice_lora_*/
```

### 9.2 設定（一次性）

在 M2 建立 `~/.aispeech_3090.env`：

```bash
AISPEECH_3090_HOST=3090         # SSH host alias（在 ~/.ssh/config 設定）
AISPEECH_3090_PATH=/Y/Projects/aiSpeechMulti
```

> 詳細 SSH 設定見 `docs/finetune_setup_3090.md` §1.5

### 9.3 常用同步指令

```bash
# 推代碼 + 音檔上去（最常用）
./scripts/sync_to_3090.sh up

# 只推音檔（支援 wav/mp3/m4a/flac/ogg/aac）
./scripts/sync_to_3090.sh audio

# 拉特定訓練 run 的 checkpoint 回 M2
./scripts/sync_to_3090.sh down sensevoice_lora_r32_e60_v2_157gt

# 不帶 run name → 列出所有可用 run 讓你挑
./scripts/sync_to_3090.sh down

# 確認本機 vs 桌機音檔數量
./scripts/sync_to_3090.sh status

# Dry run（不執行，只看會做什麼）
./scripts/sync_to_3090.sh up -n
```

### 9.4 在 3090 跑 fine-tune

```bash
# SSH 到 3090
ssh 3090

# 進專案目錄，啟動 conda
cd /Y/Projects/aiSpeechMulti
conda activate aiSpeech_project_nightly

# 啟動 fine-tune（LoRA r32，60 epochs）
python -m aispeech finetune --mode lora --lora-rank 32 --epochs 60
```

## 🆘 12 · 常見問題

| 狀況 | 怎麼處理 |
|---|---|
| 開 http://localhost:8000 顯示「無法連線」 | 回 Terminal 看 `python -m aispeech serve all` 還在不在跑 |
| `source ./activate.sh` 顯示 conda 找不到 | 需先安裝 miniforge3：`~/miniforge3/etc/profile.d/conda.sh` 不存在 |
| capture 按 **開始監聽** 沒反應 | macOS 系統設定 → 安全性 → 麥克風權限 |
| 上傳音檔顯示「Unsupported format」 | 只接受 wav / mp3 / m4a / flac / ogg / aac |
| Grafana 進不去 | Docker Desktop 沒開，或 `docker compose` 沒跑 |
| 字幕跑出來是亂碼 | 引擎選錯（中文要選 chirp_3 / chirp_3_hans / SenseVoice） |
| Lab 開啟很慢 | 第一次載入要編譯 Streamlit，等 30 秒即可 |
| API key 錯誤 | 確認 `utils/api_keys.json` 存在且格式正確；或 `.env` 有填 |
| sync_to_3090.sh 報 HOST 未設定 | 建立 `~/.aispeech_3090.env` 填入 AISPEECH_3090_HOST |
| sensevoice_ft 顯示模型找不到 | checkpoint 在 `experiments/finetune_runs/sensevoice_lora_r32_e60_v2_157gt/best.pt`，用 sync down 從 3090 拉 |
