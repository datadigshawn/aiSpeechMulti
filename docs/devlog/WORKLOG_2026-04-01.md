# 工作日誌 2026-04-01

## 主題：新增 SenseVoice 本地端語音辨識模式（機密語音離線辨識）

### 背景

針對機密性語音資料，需要 100% 本地端執行的語音辨識方案，避免音訊上傳到雲端（Google STT / ElevenLabs Scribe）。選擇阿里達摩院的 **FunASR SenseVoiceSmall** 作為本地端引擎，特點：
- 非自迴歸架構，10 秒音訊推論僅需 ~70ms（RTF ≈ 0.04）
- 支援中/英/日/粵/韓 + 情緒辨識 + 音訊事件偵測
- 訓練資料超過 40 萬小時，辨識效能優於 Whisper

### app_api.py 即時語音辨識模組變更

1. **新增 `sensevoice_local` 串流模式**
   - `VALID_MODES` 加入 `sensevoice_local`
   - `DEFAULT_STT_BACKEND` 驗證加入 `sensevoice`
   - 新增 `_handle_sensevoice_local_mode()` handler
   - 新增 `_get_sensevoice_model()` 全域單例管理（asyncio.Lock 保護）
   - WebSocket 端點分派加入 sensevoice_local 路由

2. **sensevoice_local 模式架構**
   ```
   Browser PCM 16kHz → WebSocket → AudioBuffer（3 秒 chunk）
     → SenseVoice 本地辨識（~0.8s/chunk）
     → 簡體→繁體轉換（opencc s2twp）
     → 推播前端 + 存入 SQLite
   ```

3. **AudioBuffer 改進**
   - `__init__` 新增 `target_bytes` 參數，支援不同 chunk 大小
   - sensevoice_local 使用 3 秒（96,000 bytes），batch 模式維持 15 秒

4. **`create_stt_model()` 工廠函式**
   - 新增 `sensevoice` backend 分支

### scripts/models/model_sensevoice.py 模型封裝變更

1. **新增 `use_vad` 參數**（預設 `True`）
   - 即時模式用 `use_vad=False`：跳過 `fsmn-vad` 模型下載（ModelScope 端點不穩定）
   - 批次模式維持 `use_vad=True`：啟用 FunASR 內建 VAD 切割長音訊

2. **改用 HuggingFace 來源**
   - `hub="hf"`，模型名稱映射 `iic/SenseVoiceSmall` → `FunAudioLLM/SenseVoiceSmall`
   - `trust_remote_code=False`：FunASR >= 1.3 內建 SenseVoiceSmall，不需要遠端 model.py
   - HuggingFace 失敗時自動回退 ModelScope

3. **`disable_update=True`**：跳過每次啟動的版本檢查，加快載入速度

### 解決的技術問題

| 問題 | 根因 | 解法 |
|------|------|------|
| `SenseVoiceModel.__init__() got unexpected keyword argument 'model'` | 主目錄已有的模型封裝用 `model_name` 參數 | 修正 app_api.py 呼叫為 `model_name=` |
| `iic/SenseVoiceSmall is not registered` | ModelScope 下載不完整，缺少 model.py | 改用 HuggingFace + `trust_remote_code=False` |
| `Still waiting to acquire lock on fsmn-vad` | ModelScope lock 檔案殘留 + 下載失敗 | 即時模式用 `use_vad=False` 跳過 VAD 下載 |
| WebSocket `received 1005` 斷線 | 模型首次下載耗時過長，超過 keepalive timeout | 全域單例預載 + WebSocket 斷線容錯 |
| 辨識結果顯示為 Scribe 標籤 | 前端 stt_backend 判斷未涵蓋 sensevoice | 加入 `backend === 'sensevoice'` 分支 |
| 辨識結果為簡體中文 | SenseVoice 預設輸出簡體 | 加入 opencc s2twp 轉換 |

### 目前系統支援的辨識模式總覽

#### 即時語音辨識（WebSocket 串流）
| 模式 | 引擎 | 延遲 | 資料傳輸 |
|------|------|------|---------|
| dual | Scribe RT + Google 批次 | ~150ms | 雲端 |
| scribe_rt | ElevenLabs Scribe v2 | ~150ms | 雲端 |
| google_stream | Google gRPC 串流 | ~500ms | 雲端 |
| **sensevoice_local** | **SenseVoice（本地端）** | **~3s chunk** | **100% 離線** |
| batch | Google/Scribe 批次 | 15s | 雲端 |

#### 語音檔案辨識（批次上傳）
| 模型 | 子模型 | 資料傳輸 |
|------|--------|---------|
| Google Cloud STT | chirp_3 / chirp_2 / chirp_telephony | 雲端 |
| Google Gemini | gemini-3.1-pro 等 5 種 | 雲端 |
| OpenAI Whisper | large-v3 / turbo / medium | 本地端 |
| **SenseVoice** | **SenseVoiceSmall** | **本地端** |
| 混合模式 | Google + Gemini 融合 | 雲端 |
