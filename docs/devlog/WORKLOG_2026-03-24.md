### 2. Scribe RT 根本問題修復（model_scribe.py v2.0）

**ROOT CAUSE：websockets 16.0 API 變更**

- Conda 環境 `aiSpeech_project_nightly` 安裝的是 `websockets 16.0`
- websockets 16.0 的連線物件是 `ClientConnection`（以前是 `WebSocketClientProtocol`）
- `ClientConnection` **沒有 `.closed` 屬性**
- 舊程式：`getattr(self._ws, "closed", True)` → 找不到屬性 → 回傳預設 `True`
- 結果：`is_connected` 永遠是 `False`
- 每次 `send_audio()` 立即拋出 `RuntimeError("尚未連線")` → 音訊完全無法送達 Scribe

**修復方式：**
```python
@property
def is_connected(self) -> bool:
    if self._ws is None:
        return False
    # websockets 14+ (ClientConnection): 用 state 判斷
    if hasattr(self._ws, "state"):
        try:
            return int(self._ws.state) == 1   # OPEN = 1
        except Exception:
            return False
    # websockets < 14 (WebSocketClientProtocol): 用 closed 判斷
    return not getattr(self._ws, "closed", True)
```

**同時修復：**
- `close()` 方法改用 `self.is_connected`（避免同樣問題）
- `ping_interval=None`：停用 WebSocket ping，ElevenLabs 不回應 WS ping，啟用後約 50 秒斷線

### 4. 簡繁中文轉換（app_api.py）

使用 `opencc` 套件（已安裝於 conda env）：

```python
import opencc
_cc = opencc.OpenCC("s2twp")   # Simplified → Traditional (Taiwan)

def _s2t(text: str) -> str:
    return _cc.convert(text)
```

套用位置：
- `_handle_scribe_rt_mode()` → partial + committed 都轉換
- `_handle_dual_mode()` → scribe 的 partial + committed 都轉換
- 資料庫儲存、前端顯示均為繁體中文

轉換範例：
- `人工智能` → `人工智慧`
- `软件` → `軟體`
- `实时` → `實時`
- `现在开始录音，请说话。` → `現在開始錄音，請說話。`
