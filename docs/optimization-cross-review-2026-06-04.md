## 2. 補充 1 — 真正隱憂：21 段 test 太小，可能在「優化雜訊」

頭條數字 **25.42% 是算在 21 段 held-out 上**。在這個規模：

- LLM correction 的「+0.78pp」、dict 的「-0.11pp」**幾乎都落在統計噪音內**——21 段裡一兩段變動就 ±2~5pp。

> 🔧 **2026-06-04 實測更正**：用 paired bootstrap 實測後，LLM 改善其實**顯著**（-0.89pp，95% CI [-1.48, -0.40]，9 改善/1 退步）。原因：絕對 CER 的 CI 寬（±4.3pp），但「配對差異」的 CI 窄（±0.5pp），配對相減抵消了段落難易變異。→ 比較兩 run 要看 **paired 差異的 CI**，不是兩個平均值 CI 是否重疊。詳見 `_devlog/2026-06-04 優化作業 — 評測底盤…`。
- 各 run 之間 25.42% / 26.20% / 28.66% 的差距，**很大一部分來自「分母不同」**（21 段 test vs 63 段全集），不是真實能力差。

| 數字 | 來源 | 分母 | 可信度 |
|---|---|---|---|
| 25.42% | overlay `_source` / cer_history 最新 | **21 段 test** | 高變異 |
| 28.66% | 2026-05-01 sensevoice_ft_r32_full | **63 段全集** | 較穩 |

**建議（我認為目前 ROI 最高、計畫沒寫的一項）：**

1. 凍結一個**固定、夠大的 held-out 評測集**，每次 run 都報同一組。
2. 輸出**逐段 CER 分布 + bootstrap 信賴區間**。
3. 小資料下考慮 **k-fold 交叉驗證**取代單一 21 段 test，否則無法分辨「真進步」與「抽樣運氣」。

> 沒有這個底盤，後面每個 -1pp 的宣稱都不可信。

## 3. 補充 2 — 同分布 GT 擴充的邊際效益正在塌

## 4. 補充 3 — 計畫完全沒有「資料增強」（小資料 ASR 標配）

SpecAugment / speed perturbation / 加噪 在「1.8 小時、易過擬合（e100 比 e60 差）」的情境是**最對症的便宜藥**，
但 A1–F6 清單裡完全沒有。建議補成獨立實驗項：風險低、不需新標註。

## 5. 補充 4 — v3/v4 的「70% batch NaN gradient」不全是 dataset shift

那有**訓練不穩定**成分：`lr=1e-3` 偏高 + mp3 lossy + 長段（A012 達 225 秒）。

- 計畫 P2 已要降到 `5e-4`，方向對。
- 再加 **gradient clipping + bf16 + chunk cap 45s**，應能把 NaN 壓下去。

→ 即 A 系列不是「純粹用不了」，而是「現在的訓練配方接不住它」。
